# 实验设计说明

## 1. 三个数据集综合利用逻辑

本项目把 NBSDC 三类数据按物理层级串联：

- 集群级数据提供电价、功率上限和 Power Capping 场景，表示数据中心可用电力约束。
- 服务器级数据提供任务到达、CPU 需求、deadline 和机房/机架/服务器层级分布，表示业务负载压力。
- 芯片级数据提供 DVFS 频率、实际功率、报量功率和芯片功率上限，表示设备侧功率响应。

三层数据统一到小时尺度后，构造 `cluster_cap_norm`、`server_load_norm`、`chip_power_norm`，再计算 `power_margin_norm`。该裕度不是原始字段，而是融合后的等效指标。

## 2. 与任务书对应关系

- 算电协同：通过电价、功率上限和任务负载共同刻画调度约束。
- 异构资源：本版本不再沿用旧 CPU/GPU 合成任务模型，而是体现集群、服务器、芯片三个层级的资源异构。
- 调度优化：RH-TEO 在滚动时域内对 Token 出口区域进行分配，体现动态优化。
- 实验验证：提供策略对比、关键参数敏感性和可视化图表。

## 3. 与老师要求对应关系

- 使用真实数据：清洗并融合 NBSDC 三个 xlsx 文件。
- 不只做单一算法：对比 No-Export、Power-Margin-Only、Price-Driven、Latency-Aware 和 RH-TEO。
- 有工程链路：从原始 xlsx 到标准 CSV、融合指标、优化结果、图表输出均可运行。
- 有可解释性：功率裕度和 Token 产能折算关系在代码、README 和图表中保持明确。

## 4. 与学长初稿思路对应关系

如果初稿强调数据中心负载、电力约束和调度优化，本项目可以将其扩展为：

- 第 3 章：NBSDC 数据清洗与三层融合建模。
- 第 4 章：等效功率裕度与 Token 出口优化模型。
- 第 5 章：策略对比、敏感性分析和结果讨论。

注意不要把源数据描述为真实线上 Token 业务记录。Token 出口是基于功率裕度构建的扩展场景。

## 5. 本科论文写法提醒

- 先解释数据来源和字段处理，再解释为什么需要三层融合。
- Token 产能折算只作为可解释的建模假设，不写成真实观测值。
- RH-TEO 的目标函数写清楚收益、成本、时延、SLA 和波动惩罚即可，不需要过度复杂。
- 对 full-scale 原始任务负载不宜直接给出算法优劣结论，应作为模型适用边界讨论。
